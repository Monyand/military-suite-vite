# Military Suite — Vite на основі вибраного HTML

Базове джерело прикладного коду: **`../міл/MilitarySuite.html`**, яке користувач явно вибрав за основу. Сам файл не змінено. Контрольна сума, кількість рядків, походження модулів та подальші погоджені зміни записані в `migration-manifest.json`.

Попередній Vite-проєкт з пізнішими доробками збережено повністю в сусідній папці `military-suite-vite.before-html-base-20260919`. Поточна папка `military-suite-vite` містить версію на основі вибраного HTML з описаними нижче оновленнями.

## Один HTML для робочого ноутбука

На комп'ютері, де дозволено Node.js/npm, виконайте в папці проєкту:

```powershell
npm run build:single
```

Результат: **`dist-single/MilitarySuite.html`**. Перенесіть лише цей файл на робочий ноутбук і відкрийте подвійним кліком у браузері. Node.js, PowerShell, `start.cmd`, локальний сервер і папка `node_modules` для його роботи не потрібні. JavaScript у локальному HTML має бути дозволений політикою браузера; пакування не скасовує обмежень адміністратора.

JavaScript, CSS та шрифти включені всередину. Файл більший за старий HTML, бо бібліотеки більше не завантажуються окремо з CDN. Редаговані чотири модулі залишаються в `src/`; мініфікований результат вручну редагувати не потрібно. Команда перевіряє, що збірка не залишила окремих ресурсів, і лише після цього замінює `dist-single/MilitarySuite.html`. Початковий `../міл/MilitarySuite.html` та звичайний `dist/` вона не змінює.

Перевірка готового файлу без мережі: `npm run test:single`. Вона відкриває копію HTML через `file://`, перевіряє шрифти, збереження, вкладки, фільтри, діаграми й зашифровані бекапи в ізольованих профілях Edge на синтетичних даних.

База локального HTML може відрізнятися від бази Vite та інших локальних файлів. Переносьте записи через **«Відновити бекап»**, не розраховуйте на автоматичне спільне сховище. Надалі використовуйте той самий браузер, профіль і розташування файлу та регулярно зберігайте бекапи. Наявна необов'язкова інтеграція з дисковим сервісом на порту 8765 без сервера недоступна; браузерне збереження та файлові бекапи працюють без нього.

## Запуск через локальний сервер

Відкрийте **`start.cmd`** подвійним кліком. Він збере поточний код і відкриє програму за адресою **http://127.0.0.1:5173**. Залишайте вікно запуску відкритим; зупинка — Ctrl+C. Сервер доступний тільки на цьому комп'ютері. Зайнятий порт спричинить помилку, а не перехід на іншу адресу з порожньою базою.

Node.js має бути версії 20.19+ або 22.12+. Скрипт також знаходить наявний Node.js середовища Codex на цьому комп'ютері. Залежності вже встановлені; на іншому комп'ютері виконайте `npm ci --ignore-scripts` у цій папці.

Для розробки: `npm run dev`. Для звичайної багатофайлової збірки: `npm run build`; для її перегляду: `npm run preview`. Не запускайте dev та preview одночасно. Кореневий `index.html` і `dist/index.html` потребують сервера; подвійним кліком відкривається саме `dist-single/MilitarySuite.html`.

## Дані та бекапи

Браузерна база старого HTML (`file://`) і нової програми (`http://127.0.0.1:5173`) — різні сховища. Для перенесення скористайтеся верхньою кнопкою **«Відновити бекап»**: виберіть єдину копію, введіть пароль, перевірте попередній перегляд і підтвердьте відновлення. Дані користувача автоматично не імпортувалися і не очищалися.

Попередній Vite-проєкт використовував цю ж адресу: якщо ви вже працювали в ньому, його браузерні дані залишаються. До будь-якого відновлення зробіть копію поточного стану. Відновлення замінює набори даних, як у вибраному HTML; наявне правило збереження позначок ПБД не змінено. Інший браузер, профіль, порт чи `localhost` замість `127.0.0.1` означають інше сховище.

## Структура

```text
src/
  modules/events/       події та втрати противника
  modules/medical/      медичний облік
  modules/personnel/    журнал о/с і його рідний DOM-інтерфейс
  modules/documents/    завдання, втрати ОВТ, статус позицій
  core/                сховища, бекапи, довідник анкет, спільні підсумки
  app/                 оболонка, навігація, завантаження чотирьох модулів
  styles/              стилі
```

Замість конкатенації — явні ES-імпорти й експорти. Чотири блоки утворюють окремі JS-файли під час збірки. Їхні внутрішні великі компоненти поки збережені: це перенесення, а не переписування логіки чи штучне скорочення рядків. Редагуйте `src/`, не файли `dist/`.

Початкові зміни для Vite обмежувалися збиранням JSX/CSS, локальними бібліотеками, точками входу й порядком ініціалізації журналу о/с. Його оригінальна `runMigrations` збережена. Подальші погоджені зміни модулів відмічаються окремо в `migration-manifest.json`; початкові контрольні суми не переписуються. Пізніші архіви довідників, загальний індикатор збереження та нова схема міграцій із попереднього `src/` **не додані**. Анкетні знімки працюють саме так, як у вибраному HTML.

## Медичні діаграми — 20.09.2026

У вкладці «Аналітика» поденна та погодинна діаграми мають незалежні налаштування: окремі типи, довільна сума вибраних типів, швидкі набори, лінії/стовпчики та власне скидання. Пунктирна блакитна лінія — зведення. Верхні галочки типів залишилися для кругової структури втрат; «Цифри» та «у %» діють на діаграми, відсотки для часових графіків обчислюються від загальної кількості в кожному ряді.

Старе глобальне «Об'єднати групи» прибрано: нові налаштування не змінюють записи, черги евакуації або звіти. Вони зберігаються в `med_settings_v3.medicalChartViews` і входять у бекап. Excel містить окрему колонку зведення, але в загальному підсумку кожен тип враховано лише один раз. Дні без записів збережені; дати в експорті включають рік. Старе правило міграції бойових травмувань у поранення не змінене.

Запуск не залежить від CDN; шрифти й бібліотеки постачаються локально. Наявні посилання на шрифти у друкованому HTML-звіті та необов'язковий локальний сервіс резервування на порту 8765 залишені як у джерелі. Дані не надсилаються до нового хмарного сервісу.

## Статус позицій — звірка документів, 20.09.2026

- Верхні картки: виставлення, облаштування, зняття та знищення окремо. Другий ряд — п’ять карток категорій; «ОВгП» об’єднує мінометні та вогневі. Картки рахують **документальні записи за період**, а не кількість фактично наявних позицій; натискання фільтрує журнал.
- Історію з постійним ID може починати виставлення або явно внесене нове облаштування. Виставлення після облаштування продовжує цю історію. Переміщення й перейменування вимагають попереднього виставлення на дату документа. Після документального закриття нові дії в цьому ланцюжку блокуються. Повторне виставлення після закриття створює новий ланцюжок, навіть якщо назва повторюється.
- «Історія» біля запису та список «Відкрити історію позиції» показують усі пов’язані документи, незалежно від фільтрів. Виправлення й видалення з цього оновлення фіксуються окремими знімками `positionAudit` та входять у єдиний зашифрований бекап. Видалення/редагування, яке пошкодить наступні зв’язки, блокується.
- Поле «№ Позатермінового донесення» обов’язкове, якщо явно не поставлено «Очікую номер донесення». Записи без номера пульсують червоним і мають текстове попередження; внесення номера прибирає нагадування. За системного налаштування зменшеного руху залишається статична червона підсвітка.
- Старі записи автоматично не переписуються й не видаляються. Однозначні зв’язки за назвою/датою читаються зі старих даних; неоднозначні записи потрапляють до «Потребує звірки». Для них можна виправити номер без вигаданого виставлення або додати відсутній документ і явно вибрати зв’язок. Якщо документи мають одну дату, порядок введення використовується як резервний порядок; явний зв’язок із пізніше внесеним виставленням цієї ж дати зберігає логічну послідовність.
- Старі Excel-файли з 5–6 колонками підтримуються. Новий експорт додає категорію, нову назву та ID зв’язку в кінці. Історія виправлень входить до бекапу, але не до Excel. Імпорт історичних неповних записів не блокується: вони залишаються видимими для звірки.

## Спільні довідники — 20.09.2026

Кнопка «Спільні довідники» у верхній панелі відкриває шість розділів: документальні назви, фактичні місця, підрозділи, причини, засоби ураження та звання.

1. Додайте стандартні назви списком або одразу правила «багато варіантів → одна назва». Для різних цільових назв вставте пари через Tab (дві колонки Excel), `→` або `=>`.
2. Перевірте нерозпізнані значення: видно кількість входжень і модулі-джерела. «Це стандарт» додає назву; «Взяти для правила» підставляє її в редактор. Суперечливі правила та приховані ланцюжки замін блокуються.
3. «Зберегти довідники» оновлює тільки довідники й підказки форм. Наявні записи та вже вибрані значення відкритих чернеток не змінюються.
4. Для виправлення наявних записів натисніть «Перегляд цього розділу» або «Перегляд усіх замін». Перевірте зміни, задайте пароль від 12 символів, збережіть чернетки, закрийте інші вкладки та підтвердьте операцію.
5. Перед записом створюється повна захисна копія AES-256-GCM. Вона зберігається в браузері та пропонується для завантаження. Після застосування потрібне перезавантаження. Відкат: «Відновити бекап» → «Попередній стан» або завантажений `.mils.enc`, із тим самим паролем.

Замінюються лише повні значення явно визначених текстових полів. Регістр, зайві пробіли та Unicode-варіанти нормалізуються для зіставлення; фрагменти коментарів, ПІБ, позивні, ID, статуси й старі знімки аудиту не переписуються. Поле «Позивний / Підрозділ» виключене за замовчуванням і вмикається окремо. Медичні анкетні знімки мають власні поля підрозділу/звання: вони показані в перегляді й виправляються лише після підтвердження.

За наявності документального реєстру підказки документальних місць беруть лише останні назви його незакритих історій без виявлених помилок. Вони оновлюються після збереження документів у медичних формах, журналі подій та документах ОВТ. Уже вибране старе значення збереженого запису/відкритої форми залишається доступним; історичні записи автоматично не перейменовуються. Якщо реєстру ще немає, працює попередній список підказок. Це обмін назвами документів, не синхронізація фактичних позицій журналу О/С. Фактичні місця — окремий список. Старі медичні `sectors` не видаляються: їх можна вручну рознести між двома розділами.

Довідники, правила та журнал масових виправлень зберігаються в `document_dictionaries_v1` і входять до єдиного бекапу. Попередній перегляд нічого не записує. Якщо будь-які збережені дані змінилися після перегляду, застосування блокується. Збій запису використовує наявний механізм відкату єдиного бекапу; модулі залишаються призупиненими до перезавантаження.

## Масові записи й зв’язки документальних позицій — 20.09.2026

- У «Статусі позицій» є кнопка «Масове внесення / перейменування». Для виставлення вставляйте по одній назві на рядок або три колонки з Excel: назва, категорія, № донесення. Для перейменування — дві колонки або `попередня назва → нова назва`. До 1000 рядків за один раз.
- Укажіть спільну дату вже здійсненої дії, категорію, донесення та за потреби ПБД/примітку. Окремий номер із третьої колонки переважає спільний. Відсутність номера дозволена тільки після явного підтвердження очікування; такі записи мають червоне нагадування.
- «Перевірити список» показує пакет до запису. Повтори, відсутні вихідні назви, конфлікти й порушення історії блокують весь пакет, без часткового імпорту. Взаємні перейменування підтримуються завдяки спільному `renameBatchId`. Попередні рядки й назви не змінюються — додаються нові документи та аудит.
- Перед масовим записом обов’язкові пароль від 12 символів і зашифрована захисна копія. Вона завантажується та доступна через «Відновити бекап» → «Попередній стан». Збереження пакета виконується одним записом документального журналу; повторне натискання й застарілий перегляд захищені перевірками.
- Облаштування може почати історію до виставлення. При пізнішому виставленні оберіть «Продовжити історію облаштування». Також можна додати ранній документ облаштування до вже внесеного пізнішого виставлення, явно вибравши зв’язок. Старі непов’язані записи не перетворюються на нові історії автоматично.
- Для вже здійсненого переміщення є необов’язкові «На місце іншої позиції» та «Нова назва позиції». Посилання і назва іншої позиції на дату документа зберігаються в цьому записі; інша позиція не закривається та не змінюється автоматично. Зв’язок із собою/відсутнім на дату записом і конфлікти назв блокуються.
- Історія показує облаштування, виставлення, перейменування та посилання при переміщенні. Excel отримав нові колонки в кінці, старі колонки не переставлено. Повний бекап зберігає зв’язки, групи перейменувань та аудит. Нові форми призначені для поточної або минулої дати, не планування майбутніх дій.

## Доповідь зі збереженої події ШД — 21.09.2026

- На картках ШД у «Втрати Противника» є кнопка «Доповідь». Вона активна після внесення коректного часу завершення. Відкривається редагована чернетка позатермінового донесення за наданим шаблоном, із копіюванням тексту. Якщо браузер забороняє буфер обміну, текст виділяється для Ctrl+C.
- Джерело — лише вибрана подія: дата/час, напрямок, збережена документальна назва, чисельність, техніка та її власні поля наших втрат. За уточненим запитом користувача «ЗНИЩЕНО» об’єднує `count200 + count200Unconfirmed + count200Discovered` усіх рядків; «ПОРАНЕНО» — суму `count300`. У вікні чернетки показано склад об’єднаного підсумку. Категорії в первинних записах не змінюються. Фактичне місце, нинішня перейменована позиція або медичні підсумки за день не підставляються замість даних події. Дані полонених залишаються поза цим підсумком.
- Кількість втрат пишеться цифрами й українськими словами. За трьох збережених нульових значень наших втрат — «Втрати о/с відсутні». За нульових підсумків 200/300 — «результат: уточнюється». Незаповнені/некоректні основні поля позначаються для уточнення, а не підмінюються нулями; відсутні додаткові категорії 200 у старих записах рахуються як нуль. Перехід через північ без явної дати завершення потребує перевірки.
- Фрази «Позиція не втрачена. Противник успіху не мав» взяті з шаблону користувача, а не обчислюються з події: у вікні явно нагадано перевірити їх. Тестова подія має окреме попередження. Відправлення звіту не виконується.
- Чернетка не змінює базу, аудит, ПБД чи фільтри; її редагування після закриття не зберігається. Перед закриттям скопіюйте потрібний текст.

## Форми документальних позицій — 21.09.2026

У полях «Позиція з реєстру» та «На місце іншої позиції» працює пошук за частиною назви без урахування регістру. Вибір — натисканням або стрілками й Enter. Підказки показують категорію, дату та номер документа; однойменні історії мають окремі ID. Просто введений текст не створює зв’язок і не дозволяє випадково зберегти попередній вибір.

«Нова назва позиції» доступна для будь-якої документальної дії. Порожнє поле залишає назву без змін (крім дії «перейменована», де назва потрібна). Статус і нова назва зберігаються одним записом; старі документи та назви зберігаються в історії. Перевірки конфліктів і наступних зв’язків діють для всіх статусів. Картка/фільтр «ОВгП» підсумовує «Мін. Батр.» та «Вогневі», не переписуючи категорії документів; окремі категорії залишені у формах і додатковому фільтрі.

## Шаблони ОВТ — 21.09.2026

Єдина широка форма: ліворуч поля, праворуч постійний живий текст і копіювання; на вузькому екрані блоки розташовані один під одним. Перемикачі «Позиція у документі / Маршрут», «Серійний номер / VIN / Заводський номер», «Номер авто / Бортовий номер» залишають лише потрібні поля. Неактивні старі значення не видаляються.

Для транспорту — статуси «ЗНИЩЕНО» та «ПОШКОДЖЕНО». Тип транспорту зі спільного довідника використовується в основному тексті. Після «Унаслідок події» додається лише вибраний або введений текст наслідку — без автоматичної назви транспорту. Наслідки пропонуються лише для вибраного статусу й відповідного типу. Зміна статусу або типу очищує попередній наслідок із поясненням. Старі наслідки без статусу зберігаються в секції «Нерозподілені»: призначте статус у довіднику, щоб увімкнути підказку. Пропущені відомості позначаються дужками; пунктуація формується автоматично.

Нові власні моделі, завдання, маршрути, типи, описи й наслідки автоматично додаються після успішного збереження події. Моделі, завдання, маршрути та описи прив’язані лише до типу транспорту: статус їх не обмежує, зокрема для раніше збережених фраз. Статус використовується тільки для наслідків. Повтори об’єднуються без зміни записів. Стандартні підказки «Пікап» і «Позашляховик» для моделей прибрані; при першому переході до нового довідника підтягуються моделі зі старих подій та власного списку номенклатури. Моделі транспорту редагуються у «Спільні довідники» → «Шаблони ОВТ» → «Номенклатура / Модель».

Скасовані чернетки, координати й номери не стають шаблонами. При помилці запису довідника подія залишається збереженою, а повідомлення пропонує повторну спробу. У довіднику можна змінити тип для фраз або зробити їх спільними для всіх типів. Дані шаблонів входять до AES-бекапу. Старі записи та початкові одинадцять колонок Excel сумісні; нові поля додані в кінець.

## Перевірки збірки

- `npm test` — відповідність вихідному HTML, контрольна сума, шифрування/відкат, моделі документів та підсумків, довідник анкет і шаблон доповіді.
- `npm test -- --browser` — за запущеної програми: вкладки, анкети, фільтри, бекапи, діаграми, Excel та відновлення після помилок. Потрібен Edge; інший канал Playwright задається `SUITE_BROWSER`, адреса — `SUITE_TEST_URL`.

Тести працюють із синтетичними даними в ізольованих браузерних профілях. `scripts/extract-html.cjs` — одноразовий скрипт перенесення; повторно запускати його для роботи не потрібно.
